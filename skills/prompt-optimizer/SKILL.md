# 提示词优化

把用户给的一句话改成模型能照着执行的提示词。默认只交成品，不交过程。

## 默认输出

一个代码块。别的不写。

```
<优化后的提示词>
```

- 代码块里只放提示词本身：不放"以下是优化后的版本"、不放标题、不放逐条说明。
- 代码块外不写归因表、样本、指标、token 记账、改动清单。
- 只改用户给的那一句，不顺带重写他没提的部分。

## 怎么改

照这四条改，靠改措辞，不靠加条数：

1. **形容词换成可判定的量**：`简洁` → `不超过 3 句、每句 15 字内`；`最合适最受欢迎` → `相关性优先，打平时比 stars`。
2. **模糊条件换成可观察的事实**：`不确定时` → `输入中没有给出条款时`。
3. **一句话只放一件事**：身份、这次要它做的事、长期规则，分开写。
4. **已有载体承载的内容删掉**：身份、已配置好的事实、已存在的规则，不要重写。

删掉的和加上的一样多。净增超过 20% 就先想还能删什么。

## 语言

输出的语言跟用户输入一致。用户用中文，就给中文提示词。

目标模型只吃英文时（图像生成常见），先问一句要中文还是英文，不要自己决定。

## 先确认，再输出

输出前看这句话缺不缺**会改变结果**的信息。缺，且不同答案会产出不同提示词时，用 `ask_user_question` 弹一次选择框，拿到答案再给代码块。

| 缺什么 | 选项要具体到这个程度 |
|---|---|
| 目标模型或载体 | 图像模型 / 文本模型 / 给 agent 的指令 |
| 用途与场景 | 商用广告 / 个人创作 / 内部文档 |
| 风格或语气 | 写实摄影 / 卡通插画 / 3D 渲染 |
| 长度与格式 | 一句话 / 结构化段落 / JSON 契约 |

- 一次问 1–3 个，每个给 2–4 个互斥选项，其中一个可以是「你来定」。
- 选项要能直接选。不要问「你想要什么风格」这种开放问题。
- 没有 `ask_user_question` 时，用一行列出问题然后**停住**，不要自己替用户回答。
- 信息已经够产出唯一合理结果时，不要问。
- 缺的是原文本身时，只要原文。

问完直接给代码块，不要复述用户的选择。

## 用户明确要求时才展开

只有用户说"为什么会这样 / 帮我验证 / 排查一下"时，才给完整诊断：证据 → 归因 → 改动 → 验证 → 记账。默认模式不要主动给。

## 红线

- 输出超过一个代码块
- 用户没说风格/用途/目标模型，就自己替他挑了一个
- 用户用中文，却只给英文提示词且没有先问
- 换同义词、加"你是世界级专家"、加感叹号、加 emoji 当作优化
- 只加规则不删规则
- 把用户抱怨直译成规则（"太啰嗦" → 加一条"不要啰嗦"）
- 声称提升却一次都没跑过

## DSH 里的提示词载体

| 载体 | 位置 | 注意 |
|---|---|---|
| `AGENTS.md` | `~/.dsh/AGENTS.md` 全局，项目内同名覆盖 | 每轮进 prompt，按 token 记账 |
| agent preset | YAML 声明，经 bundle patch 安装 | 不能改文件，改声明后重装 |
| 工具 description | 工具定义 | 写行为不写实现，参数规则放参数上 |
| `SKILL.md` | `~/.dsh/skills/<name>/SKILL.md` | `description` 只写触发条件；含「冒号+空格」会 YAML 解析失败、被静默跳过 |

写成这四类之外的东西（schema、校验器、数据管道）通常比改措辞有效，见 references/failure-modes.md；改哪一层、怎么验，见 references/dsh-surfaces.md。
